## MASTER REVIEW CORRECTIONS (APPLIED)

Standardized file limits:

- UI component: max 150 lines.
- Custom hook: max 100 lines.
- API route: max 120 lines.
- Utility: max 50 lines.
- Page: max 200 lines.

Standardized architecture:

- Production flow MUST be UI -> Hook -> RTK or local state -> Service -> Firestore/API.
- Dummy-data flow MUST be UI -> Hook -> centralized `src/data` selectors/adapters.
- UI components MUST NOT import raw dummy arrays, call Firestore/API directly, or contain business logic.

Standardized UI rule:

- Every module page MUST include a page header, analytics cards when metrics exist, toolbar when actions/search/filtering exist, table or grid for list data, pagination for paginated data, and all required edge states.
- A table and grid are NOT both mandatory unless the module exposes a view toggle.

Standardized permissions:

- Protected routes MUST check authentication before rendering protected content.
- Navigation, buttons, actions, hooks/services, and data access MUST enforce role/permission checks.
- Permission-denied UI is REQUIRED and MUST be localized.
